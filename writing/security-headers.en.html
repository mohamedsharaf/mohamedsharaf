Some security work takes months. This takes an afternoon. A handful of HTTP response headers tell the browser how to treat your site, and together they shut the door on clickjacking, protocol downgrades, content sniffing and a large share of cross-site scripting. You add them once, at the web server, the CDN or the framework, and every page benefits.

The six that matter

Strict-Transport-Security (HSTS)

Tells browsers to use HTTPS only, even if someone types or clicks an http:// link. That blocks downgrade tricks on public Wi-Fi.

Strict-Transport-Security: max-age=31536000

Add includeSubDomains only when every subdomain really serves HTTPS, and think twice before preload: it is easy to join the browsers’ preload list and slow to leave it.

Content-Security-Policy (CSP)

The most powerful one. It lists where scripts, styles, images and connections may come from, so an injected script from somewhere else simply doesn’t run.

Content-Security-Policy: default-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'

It is also the one that can break your site, because real pages load things from many places. Roll it out in stages: start with Content-Security-Policy-Report-Only, watch what would have been blocked, adjust, then enforce. Avoid 'unsafe-inline' for scripts; use hashes or nonces instead.

X-Content-Type-Options

X-Content-Type-Options: nosniff

Stops the browser from guessing that an uploaded “image” is really HTML or JavaScript. One line, no downside.

Framing protection

X-Frame-Options: DENY

Stops other sites from loading yours in an invisible frame to trick users into clicking. The modern equivalent is frame-ancestors in your CSP; sending both is fine.

Referrer-Policy

Referrer-Policy: strict-origin-when-cross-origin

Keeps full URLs, which sometimes contain tokens or search terms, from being sent to other websites.

Permissions-Policy

Permissions-Policy: camera=(), microphone=(), geolocation=()

Turns off browser features your site doesn’t use, so a compromised script can’t ask for them either.

Two to stop sending

  • X-XSS-Protection is obsolete; modern browsers removed the feature it controlled.
  • Server and X-Powered-By with exact version numbers only help attackers pick an exploit. Remove the version, or the header.

Check your work

Open your browser’s developer tools, look at the response headers of a page, and test the site properly after each change, including login, payments and any embedded content. Free online header scanners will grade your site too. Aim for all six, and treat the CSP as a small project of its own.
