Kevin Schroeder, who taught Zend Framework training courses, noticed that the plugin architecture confused students until they saw the request lifecycle drawn out. Here is that flow for Zend Framework 1, as hooks you can attach code to:

  1. routeStartup: before the URL is matched
  2. routing: the router picks the module, controller and action
  3. routeShutdown: after routing
  4. dispatchLoopStartup: once, before dispatching starts
  5. the dispatch loop, for each action (an action can forward to another):
    • preDispatch (plugins), then the controller’s init(), preDispatch(), the action itself, and postDispatch()
    • postDispatch (plugins)
  6. dispatchLoopShutdown: once, after the loop
  7. the response is sent

Rule of thumb from that era: front controller plugins for things that apply to every request (authentication, HTTPS, logging), action helpers for things specific controllers need.
