Last week Microsoft confirmed two Exchange Server zero-days (CVE-2022-41040 and CVE-2022-41082), already used in attacks. Together they can let an attacker run code on the server. They need an ordinary mailbox login first, which attackers can usually get through phishing.

There’s no patch yet. Microsoft has published a mitigation, a URL rewrite rule, and has already had to update it once because researchers found ways around the first version.

If you run Exchange on your own servers:

  1. Apply the latest mitigation (or let the Exchange Emergency Mitigation Service do it) and check again in a few days.
  2. Block remote PowerShell for normal users. It’s rarely needed.
  3. Look for web shells and odd processes started by IIS.
  4. Install the patch the day it ships.

And the bigger question. After ProxyLogon, ProxyShell and now this, ask whether running Exchange yourself is still worth it. For most small and medium companies, hosted mail is now the safer choice.
