لاحظ كيفن شرودر، الذي كان يدرّس دورات Zend Framework، أن بنية الإضافات كانت تربك الطلاب حتى يروا دورة حياة الطلب مرسومة. وهذا هو التسلسل في Zend Framework 1، كنقاط يمكنك ربط كودك بها:

  1. routeStartup: قبل مطابقة الرابط
  2. التوجيه: يختار الموجّه الوحدة والـ Controller والـ Action
  3. routeShutdown: بعد التوجيه
  4. dispatchLoopStartup: مرة واحدة قبل بدء التنفيذ
  5. حلقة التنفيذ، لكل Action (ويمكن لأي Action أن يحوّل إلى غيره):
    • preDispatch (الإضافات)، ثم init() وpreDispatch() الخاصة بالـ Controller، ثم الـ Action نفسه، ثم postDispatch()
    • postDispatch (الإضافات)
  6. dispatchLoopShutdown: مرة واحدة بعد الحلقة
  7. إرسال الاستجابة

القاعدة العملية في تلك الفترة: إضافات الـ Front Controller لما ينطبق على كل طلب (التحقق من الدخول، HTTPS، السجلات)، ومساعدات الـ Action لما تحتاجه Controllers بعينها.

اقرأ المقال الأصلي: Zend Framework MVC Request Lifecycle، بقلم كيفن شرودر.
